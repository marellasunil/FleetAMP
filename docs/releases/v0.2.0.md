# FleetAMP v0.2.0 — Governed Fleet Management Preview

FleetAMP v0.2.0 adds the governance workflow required for teams to propose,
review, deploy, and audit OpenTelemetry Collector configuration changes. It is
a pre-1.0 community preview for evaluation and controlled single-server pilots,
not yet a supported production release.

## Highlights

- Resource-scoped Group Owner role with access limited to assigned groups
- Flexible ownership groups built from user-defined exact-match key/value conditions
- Active-group overlap protection so one Collector has one ownership and governance boundary
- Human-readable group names with immutable slug identifiers for backend relationships and URLs
- Multi-group user membership, last-login visibility, timezone preferences, and self-service password reset
- Shared FleetAMP logo across the application shell, authentication experience, and repository documentation
- Group-owned configuration authoring with section-based editing
- Admin policies for protected configuration sections such as exporters and service wiring
- Complete Collector YAML reconstruction and validation before an immutable version is saved
- Configuration revalidation before a deployment request enters approval and again before approval
- Admin approval queue with status filters and dedicated previous-versus-proposed comparison
- Snapshotted Collector targets, validation status, requester identity, version, and expiry
- Selectable approval validity of 7, 30, 60, or 90 days, with expired requests retained for audit
- Optional email notifications for Admins and affected Group Owners
- Per-agent deployment history with a single automatic rollback attempt after failed delivery
- Central-versus-agent configuration comparison and semantic drift details
- Report-only or enforce-approved-configuration drift policy
- Group drift summaries and append-only audit activity
- Administration, Management, Instrumentation, Intelligence, and Observe navigation sections
- Visible Upcoming pages for instrumentation guides, blueprints, pipelines, AI insights, and MCP

## Security and governance boundaries

- Group Owners cannot access the global Fleet, approval queue, audit log, or Administration pages.
- Requesters cannot approve or reject their own deployment requests.
- Group selectors may use managed or approved imported metadata; optional deployment labels only narrow targets inside the selected group.
- Collector-level configuration authoring is disabled; Groups are the authoring and approval boundary.
- Read-only configuration sections are enforced on the server, not only in the browser.
- AI and MCP capabilities shown in the UI are roadmap placeholders and cannot perform operations.
- Email delivery failures are logged and do not block control-plane state transitions.

## Upgrade notes

- Back up the FleetAMP data directory and SQLite database before upgrading.
- Existing databases are migrated automatically for Group Owners, approval review and expiry fields, rollback metadata, drift policy, audit records, and user notification email addresses.
- Configuration versions created before v0.2.0 remain available to existing deployment history, but are unscoped. Recreate them from the appropriate Group before submitting a new approval request.
- Review configuration-section policies after upgrading. Exporters and service pipeline wiring remain protected for non-Admin authors by default.
- Configure `FLEETAMP_OTELCOL_BINARY` when distribution-aware Collector validation is required.
- SMTP settings are optional; see the README for the supported environment variables.

## Known limitations

- Single FleetAMP instance with SQLite storage; no HA or PostgreSQL backend
- No OIDC or external identity-provider integration
- No certificate-to-agent authorization mapping
- No canary or staged rollout orchestration
- No partial `conf.d` configuration delivery
- No Collector binary or package upgrade management
- No packaged Kubernetes deployment for FleetAMP
- Grafana Alloy is not yet a validated managed-agent target
- No production-scale or performance certification

Use this release in a test environment first. Validate approval, deployment,
rollback, and drift behavior with representative Collectors before a broader pilot.

## Download and verify

Download the archive for your architecture together with `SHA256SUMS`:

- `fleetamp_0.2.0_linux_amd64.tar.gz`
- `fleetamp_0.2.0_linux_arm64.tar.gz`

Verify the download before extracting it:

```bash
grep -F '  fleetamp_0.2.0_linux_amd64.tar.gz' SHA256SUMS | sha256sum -c -
tar -xzf fleetamp_0.2.0_linux_amd64.tar.gz
cd fleetamp_0.2.0_linux_amd64
./fleetamp --version
```

The archive includes systemd examples and the user-service installer. Read
`deploy/systemd/README.md` before installation.
